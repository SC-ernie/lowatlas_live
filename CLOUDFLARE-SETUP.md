# Cloudflare setup — Lowatlas security baseline

This is the checklist behind the **Security** section of the site. Do it once for
lowatlas.com, then repeat the relevant parts for each client domain.

Everything below works on Cloudflare's **Free** plan. Limits worth knowing: the Free plan
includes the **Cloudflare Free Managed Ruleset** (not the full managed or OWASP rulesets),
**5 custom firewall rules**, **Bot Fight Mode** (on/off only, can't be tuned), and
**Turnstile** (free, up to 20 widgets per account).

Where things live:

| What | Where |
|---|---|
| Content Security Policy (blocks third-party scripts) | `<meta>` tag in every page + `_headers` + Cloudflare header rule |
| Other security headers | `_headers` (Cloudflare Pages) or a Cloudflare header rule (GitHub Pages) |
| HTTPS, DNSSEC, bots, firewall | Cloudflare dashboard |
| Contact for security reports | `.well-known/security.txt` |

---

## 1. Zone basics (per domain)

1. **DNS** → make sure the website records are **Proxied** (orange cloud).
2. **SSL/TLS → Overview** → set mode to **Full (strict)**. (GitHub Pages and Cloudflare Pages both have valid certificates, so strict works.)
3. **SSL/TLS → Edge Certificates**:
   - **Always Use HTTPS**: on
   - **Automatic HTTPS Rewrites**: on
   - **Minimum TLS Version**: 1.2
   - **HSTS**: enable, max-age 12 months. Leave **preload** off (hard to undo). Only tick *include subdomains* if every subdomain is HTTPS.
4. **DNS → Settings → DNSSEC** → enable, then copy the **DS record** into the domain registrar. Also turn on the registrar's **transfer lock**.

## 2. Bots and firewall

1. **Security → Bots** → **Bot Fight Mode**: on. (Watch for false positives in the first few days. It can't be bypassed by custom rules, only turned off.)
2. **Security → WAF → Managed rules** → confirm the **Cloudflare Free Managed Ruleset** is deployed.
3. **Security → WAF → Custom rules** → create one rule to challenge scanner paths. Only for static sites that don't run WordPress or PHP:

   ```
   (http.request.uri.path contains "/wp-admin") or
   (http.request.uri.path contains "/wp-login.php") or
   (http.request.uri.path contains "/xmlrpc.php") or
   (http.request.uri.path contains "/phpmyadmin") or
   (http.request.uri.path contains "/.env") or
   (http.request.uri.path contains "/.git")
   ```

   Action: **Managed Challenge** (or Block). This uses 1 of the 5 free custom rules.
4. Optional: a simple IP-based **rate limiting rule** on any path that has a form.

## 3. Security headers

The full list is in `_headers`.

- **If the site is on Cloudflare Pages**: nothing to do, `_headers` is applied automatically.
- **If the site stays on GitHub Pages** (GitHub ignores `_headers`): in Cloudflare go to
  **Rules → Transform Rules → Modify Response Header → Create rule** → name it *Security headers* →
  apply to **All incoming requests** → add each header from `_headers` using **Set static**.
  The Content-Security-Policy header here adds `frame-ancestors 'none'`, which the `<meta>` version can't do.

Verify with `curl -I https://lowatlas.com` and at securityheaders.com.

## 4. Email spoofing protection (per client domain, DNS tab)

- **SPF** (one record per domain). Google Workspace example: `v=spf1 include:_spf.google.com ~all`
- **DKIM**: generated by the email provider (Google Workspace: Admin console → Apps → Gmail → Authenticate email). Add the TXT record it gives you.
- **DMARC**: start in monitor mode, tighten after a few weeks of clean reports:
  `_dmarc` TXT → `v=DMARC1; p=none; rua=mailto:you@yourdomain.com`, later `p=quarantine`.
- Domain that **never sends email**: SPF `v=spf1 -all` and DMARC `v=DMARC1; p=reject`.

## 5. Forms (client sites only)

Use **Turnstile** instead of captchas: dashboard → **Turnstile** → add a widget for the hostname.
It loads a Cloudflare script, so on that page the CSP must allow it:
add `https://challenges.cloudflare.com` to `script-src` and `frame-src`.
Don't add Turnstile to lowatlas.com itself: this site has no forms.

## 6. Account hygiene (per client)

- 2FA on the registrar, Cloudflare, Google, and Meta accounts.
- The **client is the owner**; you work as a manager. Never ask for passwords.
- Registrar auto-renew on, and the renewal email goes to the client.

## 7. Analytics, trackers, and consent

lowatlas.com ships with **no analytics, pixels, or third-party scripts**, and the CSP enforces it.

- Cloudflare's dashboard traffic stats are measured at Cloudflare's edge and add nothing to your pages.
- Cloudflare **Web Analytics** (the JavaScript beacon) is a script. Leave it off unless you update the CSP and add a consent step first.
- If you add Google Analytics, a Meta Pixel, a Google Ads tag, or a chat widget on any site: update the CSP (every page's `<meta>`, `_headers`, and the Cloudflare header rule), add consent-gated loading, and update the privacy page. Ask Claude to build the consent step.

## 8. One remaining third-party request

The two concept photos (Modern Barber, Detailing Studio) are loaded from `images.unsplash.com`.
It's an image, not a script, and the browser is told not to send your page address. To remove it entirely:
save both images into the repo, point the two `<img src>` values (in `index.html`, `index-es.html`, `barber*.html`, `detailing*.html`) at the local files, and delete
`https://images.unsplash.com` from the CSP in all places.
